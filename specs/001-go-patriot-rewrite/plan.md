## Summary

Fresh Go rewrite at `go.patriotpest.pro` — pixel-identical patriotic tactical theme, modular feature-flagged monolith (Standard Go Layout), OTP-only auth + casbin, MCP API (`ppc_live_`) with no customer-delete, 6-channel unified inbox (FB/IG/X/LinkedIn/SMS/voicemail) with per-channel token settings, SurrealDB persistence, independent of `www`/`test` until vetted.

## Technical Context

**Language/Version**: Go 1.22+
**Primary Dependencies**: `chi/v5`, `surrealdb.go`, `casbin/v2`, `go-playground/validator`, `templ`, `go-chi/cors`, `slog`/`otel`, `ogen` (OpenAPI)
**Storage**: **SurrealDB** (replaces SQLite) — `SURREAL_URL` (e.g. `ws://surreal:8000`), `SURREAL_NS=patriot`, `SURREAL_DB=prod`. Records: `staff`, `customers`, `otp_codes`, `api_keys`, `posts`, `messages`, `inbox_threads`, `inbox_channel_configs`. SurrealQL migrations in `migrations/*.surql`.
**Testing**: `go test -cover`, `testcontainers-go` (surreal), table-driven, fuzz, benchmarks
**Target Platform**: Linux Dokploy VPS (`go.patriotpest.pro`), distroless:nonroot `EXPOSE 3000` behind TLS
**Project Type**: Web app (backend templ+HTMX, no SPA)
**Performance Goals**: p95 <200ms marketing, inbox poll <500ms, OTP verify <100ms, 500 concurrent sessions
**Constraints**: No `.env` commit, 12-factor env, HSTS/CSRF, 80% coverage gate, theme parity diff <2%
**Scale/Scope**: ~55 routes, 6 inbox channels, ~10 tables, single-tenant now (multi-district WA/AZ later)

## Key Decisions

| # | Decision | Alternatives Rejected | Why |
|---|----------|----------------------|-----|
| 1 | **SurrealDB** as primary (per user) | SQLite (current), Postgres | User explicitly chose SurrealDB for richer relations + embedded option; keep surreal SDK, add `SURREAL_*` env. Risk: newer SDK — spike in `research.md`. |
| 2 | **Fresh build, identical theme** — copy design tokens from `public/assets/styles.css` (`olive-950`..`orange`, Black Ops One) into new `internal/view/assets/styles.css`, but as new templ files (not git mv) | Fork `public/` verbatim | Fresh avoids carrying DeepSeek overflow bug; parity verified by visual diff, not file identity. |
| 3 | **6-channel unified inbox** as `internal/modules/inbox` + per-channel adapters `inbox/adapters/{facebook,instagram,twitter,linkedin,twilio,voicemail}` each with `Enabled` + `Ingest(ctx)`. Settings dashboard `admin/settings#channels` stores tokens encrypted in `inbox_channel_configs` (SurrealDB) | One giant webhook handler | Matches "plug in through settings, nothing hard-coded" + modular flag per channel. Logos via channel enum → `<span class="ch-badge ch-{channel}">`. |
| 4 | **MCP no-delete** — `casbin` policy never grants `customer:delete`; API mux returns 403 on `DELETE /api/v1/customers/*` even if key has `all` (filter `all` → `all-non-delete`). Audit every call. | Allow delete with extra scope | User explicit: "anything except deleting customers". Hard gate prevents agent accidents. |
| 5 | **Independent go subdomain** — `go.patriotpest.pro` A→VPS, separate deploy, `test.patriotpest.pro` untouched. Cutover only after manual QA on `go`. | Replace test | User explicit. Avoids breaking staging. |
| 6 | **OpenAPI-first** — keep `ppc_live_` + `sha256` + scopes from `api/openapi.yaml`, generate Go server via `ogen`. Add `inbox:read`, `inbox:write`, `post:create` scopes. | Hand-rolled API | Preserves MCP compat for existing super-admin keys. |

## Risks / Rollback

- **SurrealDB immaturity** — mitigate with spike + `testcontainers`; rollback to SQLite shim via `db` interface kept narrow.
- **Channel API rate limits / token expiry** — per-channel retry+backoff, `last_error` column, user-visible badge.
- **Theme parity regression** — visual diff gate in CI; rollback is static asset revert.
- **MCP no-delete bypass** — `all` scoped filtered server-side; integration test asserts 403.
- `go.` is independent — rollback is DNS no-op; `www`/`test` untouched.
